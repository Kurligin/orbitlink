# OrbitLink

Веб-сервис для проектирования спутниковой группировки и оценки доступности
связи в северных районах. Загружает сценарий, считает покрытие наземных
пунктов и сквозные маршруты «клиентский пункт → аппараты → шлюз», показывает
поведение сети при отказах аппаратов и шлюзов и сравнивает варианты
конфигурации.

**Сервис:** https://nn-hac.kurligin.ru

## Что внутри

| Каталог | Содержимое |
|---|---|
| `backend/` | Python 3.12, FastAPI, NumPy, SQLAlchemy. Расчётное ядро `orbitlink/core` не зависит от веб-слоя. 301 тест |
| `frontend/` | React 18, TypeScript, Vite. Трёхмерный глобус (globe.gl) и двумерная полярная проекция |
| `data/` | Четыре сценария организаторов, доступны в интерфейсе как готовые пресеты |
| `docs/reference_geometry.py` | Эталонный расчётный модуль организаторов — источник истины в тестах и на экране «Проверка» |
| `docs/examples/invalid_scenario.json` | Намеренно испорченный сценарий для демонстрации сообщений об ошибках |
| `deploy/` | Докерфайлы, compose, конфиг nginx, скрипт и настройки развёртывания на сервере |

## Возможности

- **Сеть.** Положения аппаратов, наземные пункты, доступные связи и выбранный
  маршрут на трёхмерном глобусе или двумерной полярной проекции с видом на
  северный полюс. Таймлайн перематывает сутки расчёта без запросов к серверу:
  позиции и связи по всем отсчётам приходят одним бинарным пакетом.
- **Редактирование конфигурации.** Очередь запуска, высота, наклонение,
  минимальный угол возвышения, дальность межспутниковой связи, RAAN и
  фазирование каждой плоскости, периоды недоступности аппаратов. Изменения
  проверяются и сохраняются отдельным вариантом, исходный сценарий не
  затирается.
- **Загрузка и выгрузка.** Собственный сценарий схемы `cosmo-A-1.0` из
  файла — при ошибках сервис перечисляет проблемные поля. Выгрузка
  изменённого сценария (загружается обратно без замечаний) и результата
  расчёта в схеме `cosmo-A-result-1.0`.
- **Устойчивость.** Ленты запаса связности по каждому пункту на 720 отсчётов:
  есть резервный путь, связь держится на единственном пути, связи нет.
  Разбор причин отсутствия связи по четырём категориям из условия задачи.
  Сравнение четырёх стратегий маршрутизации.
- **Сравнение вариантов.** Изменённые параметры человекочитаемым списком и
  разница доступности и максимального перерыва по каждому пункту.
- **Проверка.** Сверка координат, состава связей и углов возвышения с
  эталонным модулем организаторов на двадцати контрольных точках, запускается
  кнопкой.

## Расчётная модель и допущения

- Круговые орбиты, сферическая Земля, единая для всех наземных пунктов
  граница угла возвышения.
- Межспутниковая связь — по дальности и отсутствию пересечения линии связи с
  Землёй; наземные линии — по углу возвышения.
- Наземные пункты не ретранслируют трафик: клиентский пункт всегда выходит в
  аппараты, шлюз — конечный узел маршрута. При нескольких шлюзах маршрут
  строится до любого доступного.
- Геометрия зависит только от времени, а отказы и очередь запуска — маска
  поверх неё, поэтому геометрия считается один раз и переиспользуется во всех
  вариантах отказов. Прогон суток занимает около секунды.
- Маршрут ищется алгоритмом Дейкстры по графу контактов текущего отсчёта и
  сопровождается во времени: сохраняется, пока цел и не хуже лучшего
  доступного больше чем на порог, при разрыве одного ребра чинится локальным
  обходом, иначе перестраивается. Стратегии: `min_hops`, `min_latency`,
  `load_aware` (обход занятых линий), `robust` (обход связей у предела
  дальности).
- Корректность геометрии проверяется автоматически против эталонного модуля
  организаторов — тестами и эндпоинтом `/api/selftest`.

## Запуск локально

Нужны Python 3.12 (минимум 3.10) и Node.js 20.

**Бэкенд:**

```bash
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
uvicorn orbitlink.api.app:app --reload
```

API поднимется на http://localhost:8000, документация — на `/docs`. База
SQLite задаётся переменной `ORBITLINK_DB` (по умолчанию
`sqlite:///orbitlink.db`).

**Интерфейс**, в соседнем терминале:

```bash
cd frontend
npm ci
npm run dev
```

Интерфейс откроется на http://localhost:5173 и сам проксирует `/api` на
`http://localhost:8000`. Если бэкенд запущен на другом порту, задайте адрес
переменной: `ORBITLINK_API=http://localhost:8010 npm run dev`.

**Пути к данным.** При editable-установке (`pip install -e`, как выше)
каталоги `data/` и `docs/reference_geometry.py` находятся автоматически. При
обычной установке пакета процесс нужно запускать там, где рядом лежат `data/`
и `docs/`, либо указать путь переменной `ORBITLINK_REPO_ROOT`. Если по этому
пути нужных каталогов нет, сервис откажется запускаться сразу и назовёт
причину.

## Запуск через Docker одной командой

```bash
docker compose -f deploy/docker-compose.yml up --build
```

Поднимаются два контейнера: интерфейс с nginx на http://localhost:8080 и
бэкенд, к которому nginx проксирует `/api`. Порты меняются переменными
`FRONTEND_PORT` и `BACKEND_PORT`. База хранится в томе `orbitlink-state` и
переживает пересоздание контейнеров.

Остановить: `docker compose -f deploy/docker-compose.yml down`.

## Развёртывание на сервере

Сервер общий с другими проектами: порты 80 и 443 держит системный Caddy,
поэтому свой обратный прокси в compose не поднимается. Контейнеры OrbitLink
слушают только `127.0.0.1`, наружу их выпускает Caddy. Настройки портов —
`deploy/svo.env`.

**1. Выкладка приложения** — из корня репозитория:

```bash
bash deploy/deploy-svo.sh
```

Скрипт копирует исходники в `/opt/orbitlink`, собирает образы на сервере по
одному, поднимает контейнеры и проверяет, что сверка с эталоном отвечает
`ok`. Повторный запуск обновляет сервис.

**2. Домен** — один раз, вручную. DNS-запись `nn-hac.kurligin.ru` должна
указывать на адрес сервера. Затем на сервере:

```bash
sudo cp /etc/caddy/Caddyfile /etc/caddy/Caddyfile.bak-before-orbitlink
cat /opt/orbitlink/deploy/Caddyfile.orbitlink | sudo tee -a /etc/caddy/Caddyfile
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl reload caddy
```

Сертификат TLS Caddy получит сам при первом обращении к домену.

**Проверка работы:**

```bash
curl -s https://nn-hac.kurligin.ru/api/selftest | python3 -m json.tool | head
```

## Сценарий демонстрации

Все шаги выполняются в интерфейсе, мышью.

1. **Полная группировка.** Открыть сервис — загружен сценарий «Полная
   группировка». В верхней панели вьюпорта выбрать клиентский пункт, например
   C65. Двигать таймлайн или нажать воспроизведение: маршрут на глобусе и в
   сводке справа меняется от отсчёта к отсчёту. Переключить вид «3D» и
   «2D полярная».
2. **Этап развёртывания.** В левой колонке, «Параметры расчёта», переключить
   очередь запуска с 3 на 1 и нажать «Пересчитать как вариант». Доступность в
   лентах под таймлайном падает до 13–27%. Вкладка «Сравнение» по умолчанию
   сопоставляет новый вариант с исходным: видны изменённый параметр и
   разница доступности и перерывов.
3. **Отказ аппарата.** Посмотреть в сводке справа текущий маршрут, например
   `C65 → S20 → G_MUR`. Выбрать аппарат S20 в дереве «Состав группировки», в
   разделе «Отказы» добавить период его недоступности и пересчитать вариант:
   маршрут перестраивается через другие аппараты или возникает перерыв.
4. **Изменение проекта.** Изменить RAAN плоскости P2, например с 60 на 75,
   пересчитать и сравнить с предыдущим вариантом на вкладке «Сравнение».
   Нажать «Выгрузить сценарий», затем «Загрузить сценарий…» и выбрать этот же
   файл — он загружается без замечаний.
5. **Некорректный файл.** «Загрузить сценарий…» →
   `docs/examples/invalid_scenario.json`. Сервис перечисляет проблемные поля:
   шаг расчёта, ссылку на несуществующую плоскость, широту вне диапазона,
   неизвестный аппарат в отказе, перевёрнутый период.
6. **Устойчивость.** Вкладка «Устойчивость»: ленты запаса связности показывают,
   сколько времени связь держится на единственном пути; диаграмма причин —
   из-за чего пропадает связь. «Прогнать все стратегии» сравнивает четыре
   стратегии маршрутизации.
7. **Проверка расчёта.** Вкладка «Проверка», «Запустить проверку»: двадцать
   контрольных точек сверяются с эталонным модулем организаторов.

## Описание API

| Метод и путь | Назначение |
|---|---|
| `GET /api/presets` | Четыре сценария организаторов с полным содержимым |
| `POST /api/scenarios/validate` | Проверка сценария без сохранения; `ok` и список `issues` с путём и сообщением |
| `POST /api/projects` | Создать проект, базовый вариант совпадает с переданным сценарием; невалидный — `422` |
| `GET /api/projects`, `GET /api/projects/{id}` | Список проектов и проект целиком |
| `POST /api/projects/{id}/variants` | Создать вариант; в ответе дифф параметров относительно базового сценария |
| `GET /api/variants/{id}`, `PATCH /api/variants/{id}` | Вариант с диффом; обновление заголовка или сценария |
| `POST /api/variants/{id}/run` | Прогон (`strategy`, `hysteresis`, `with_backup`), кэшируется по отпечатку конфигурации |
| `GET /api/variants/{id}/export` | Результат в схеме `cosmo-A-result-1.0` с теми же параметрами, что и прогон |
| `GET /api/variants/{id}/snapshot?t_s=` | Состояние сети в один момент времени |
| `GET /api/variants/{id}/network` | Позиции и связи на всей сетке времени одним бинарным пакетом |
| `POST /api/compare` | Сравнение двух вариантов: доступность и максимальный перерыв до и после, изменённые параметры |
| `GET /api/selftest` | Сверка расчётного ядра с эталонным модулем организаторов |

Проверка корректности из командной строки:

```bash
curl -s localhost:8000/api/selftest | python3 -m json.tool | head
```
